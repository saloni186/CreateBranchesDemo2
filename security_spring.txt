Question :-JWT token ?
JWT (JSON Web Token) is a secure way to authenticate users where, after login, the server gives a token to the client, and this token is used to access protected APIs without maintaining any session on the server.

🛠️ How We Implemented JWT Authentication (Simple Process)
1. User Login

User sends username and password to the login API.

We validate credentials using Spring Security and encrypted passwords.

2. Token Generation

If credentials are valid, the server generates a JWT token.

The token contains:

Username

Roles

Expiry time

Token is signed using a secret key.

3. Token Sent to Client

The JWT token is sent back to the client.

Client stores the token (usually in memory or local storage).

4. Token Sent with Every Request

For each API request, the client sends the token in the Authorization header.

Authorization: Bearer <token>

5. Token Validation

A JWT filter runs before every request.

It:

Extracts the token

Validates signature and expiry

Gets user details from the token

6. Access Granted

If the token is valid, the user is authenticated.

Spring Security allows access to protected APIs.

No session is stored → stateless authentication.

🎯 Final Interview One-Liner

“We implemented JWT authentication by validating user credentials, generating a signed JWT token, and validating that token on every request using a filter, which allows secure and stateless access to APIs.”

difference between stored proccedor and function :-
Here’s a clear comparison between Stored Procedures and Functions in a database:

Feature	Stored Procedure	Function
Purpose	Performs a set of operations, can include business logic, data modification, or complex tasks	Returns a single value or a table and is primarily used for computations
Return Value	May return zero, one, or multiple values using OUT parameters or result sets	Must return a value using RETURN statement
Usage in SQL	Can be called using EXEC or CALL statements	Can be used directly in SELECT, WHERE, or other SQL statements
Side Effects	Can modify data (INSERT, UPDATE, DELETE)	Generally cannot modify data (read-only operations in many DBMS)
Parameters	Can have IN, OUT, INOUT parameters	Typically only IN parameters
Transaction Control	Can contain transaction control statements like COMMIT or ROLLBACK	Usually cannot handle transactions
Execution Context	Executed as a separate call, may return multiple result sets	Executed as part of a query, returns a single value or table

Method-level security with @PreAuthorize or @Secured annotations, e.g., @PreAuthorize("hasRole('ADMIN')") for admin-only methods.

URL-level security in the security configuration using HttpSecurity, specifying which roles can access which endpoints.

Ans :-@Transactional manages database transactions using Spring AOP proxies. If a transactional method is called from a non-transactional method in another Spring bean, the transaction will start normally.
